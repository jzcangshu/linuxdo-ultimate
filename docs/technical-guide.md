# Linux Do Ultimate 技术维护文档

本文面向后续维护者和二次开发者。普通用户请先阅读项目根目录的 `README.md`。

## 1. 技术栈与构建产物

源码使用 TypeScript（类型脚本语言），测试使用 Vitest（测试框架）与 jsdom（浏览器环境模拟器），构建使用 esbuild（打包工具）。Chrome 正式产物位于 `dist/extension`，Firefox 正式产物位于 `dist/extension-firefox`；两者都包含顶层 `host.js`、轻量 `bridge.js`、独立过盾模块 `challenge.js`、按需 `preview-runtime.js`、跨域请求 `background.js`、官方 Logo 图标和各自的 `manifest.json`。`src/main.ts` 及 `dist/linuxdo-ultimate.user.js` 继续保留为 V0.2 兼容与行为回归基线。

```powershell
pnpm install
pnpm test
pnpm check
pnpm build:all
pnpm package:extension
```

`package.json` 中的版本号会同时写入两个插件 manifest（清单）、兼容用户脚本头和两个正式 ZIP（压缩包）文件名。Chrome 使用 Manifest V3（第三版扩展清单）的后台 service worker（服务工作线程）；Firefox 使用后台 scripts（脚本）声明及固定 Gecko（火狐浏览器引擎）扩展 ID。除此之外不维护浏览器专属业务分支。发布前还应运行 `git diff --check` 检查空白和补丁格式。

## 2. 模块职责

| 目录或文件 | 职责 |
| --- | --- |
| `src/app.ts` | 顶层页面编排、路由同步、设置应用、各模块协调 |
| `src/core` | 设置、会话结构、默认值、迁移和存储适配 |
| `src/discourse` | 路由识别、分类读取、阅读计数追踪、帖子阅读小工具 |
| `src/tabs` | 列表页面控制器、帖子标签、内嵌页面池和标签栏渲染 |
| `src/ui` | 分屏布局、拖动比例、设置面板和全局样式 |
| `src/preview` | 悬浮预览、跨域获取、缓存和内容清理 |
| `src/frame-bridge.ts` | 内嵌帖子页与顶层页面之间的事件桥 |
| `src/credit` | 顶部 LDC 收入组件和数据请求 |
| `src/extension` | Manifest V3 插件入口、跨域请求协议和用户脚本接口兼容层 |
| `src/core/update-checker.ts` | 版本比较、更新清单校验、低频缓存与手动检查 |
| `updates/latest.json` | 当前正式版本、发布时间、发行页和结构化更新摘要 |

插件运行时保持现有业务模块不变。`host.ts` 只在非 Challenge 顶层页面调用 `startLinuxDoApp`；`bridge.ts` 只在非 Challenge 子页面调用 `bootFrameBridge`；`challenge.ts` 在所有 Linux Do frame 中独立运行过盾检测，并只重定向当前 frame；`preview-runtime.ts` 单独导出原始上游安装器；`background.ts` 将插件跨域 `fetch`（网络请求）包装为上游所需的回调结果。禁止把预览核心重新静态导入 host、bridge 或 challenge。

更新检查复用同一个后台请求兼容层，但不调用 GitHub API。顶层应用启动 20 秒后，仅在页面可见时读取仓库 `main` 分支中的 `updates/latest.json`；成功结果按当前插件版本缓存 24 小时，失败尝试在 1 小时内不自动重复。手动检查添加时间参数绕过缓存。发布时必须同步更新 `package.json`、`updates/latest.json`、更新日志和正式 Release；清单只允许指向本仓库对应版本的 GitHub Release 地址。

模块原则是让 Discourse（论坛系统）继续负责帖子正文、回复、投票、反应和时间线，脚本只负责页面编排与状态协调，不复制论坛业务逻辑。

## 3. 稳定外壳与双导航上下文

分屏开启时，`LayoutController`（布局控制器）在 `body`（页面主体）下创建稳定外壳。顶层页面继续提供顶部导航、侧栏、设置和 LDC 收入组件，但原有主内容区会隐藏。外壳内的 `ListFrameController`（列表页面控制器）维护唯一的同源列表 iframe（内嵌页面），主阅读区和可选的第二阅读区分别使用一个 `TopicFramePool`（帖子页面池）维护自己标签对应的帖子 iframe（内嵌页面）。

`frame-bridge.ts` 会根据 iframe（内嵌页面）名称区分列表角色和帖子角色。两种角色都隐藏自己的顶部导航和侧栏；列表角色保留自身原生滚动根与 Discourse（论坛系统）增量加载，帖子角色保留正文、时间线及帖子操作控件。列表导航和帖子导航拥有独立生命周期，因此任一侧刷新或跳转都不会销毁另一侧。

右键标签选择“向新的拆分视图中添加标签页”时，标签的归属会从主阅读区移动到第二阅读区，不会在两个标签栏中重复出现。脚本会先保存即时滚动位置，并尽量直接转移现有 iframe（内嵌页面）；若浏览器在重挂载时重新加载页面，则在就绪后恢复保存位置。任一阅读区关空后自动移除；主阅读区关空时，第二阅读区的现有 iframe（内嵌页面）会直接归并并扩充占满。

帖子活动页数量超过设置上限时，各页面池按最近最少使用顺序暂停非活动页面；标签状态和地址仍保留，重新激活时再创建页面并恢复滚动位置。关闭分屏后会销毁列表与两个阅读区的 iframe（内嵌页面）运行时并移除外壳监听器，防止隐藏页面继续占用资源。

## 4. 路由与直接帖子启动

主页、分类、标签、用户页、搜索和书签等非阅读路由在分屏中都由列表 iframe（内嵌页面）导航，顶层浏览器文档不再跟随这些跳转。顶层导航和侧栏点击会转发到列表页面；列表页面的普通站内导航保持在自身上下文，帖子链接则交给标签系统。

新的浏览器标签页直接进入帖子 A 时保持论坛原生阅读页，不自动改变布局。只有用户随后主动点击其他站内入口时，脚本才在当前文档内直接建立分屏：点击帖子 B 时以论坛主页作为列表并依次打开 A、B；点击分类、主页、搜索或用户页时以目标页面作为列表并保留 A。整个过程不再通过 `location.assign`（地址跳转）或临时主页交接，因此不会播放整页刷新动画，也不会清空阅读页缓存。

同帖楼层、站外链接、下载链接、在新标签打开以及带修饰键的点击保持原生行为。旧的 `direct-topic-handoff.ts`（直接帖子交接模块）仅为历史兼容保留，主程序已不再引用。

## 5. 设置与会话存储

V0.4 插件使用 Linux Do 域的 `localStorage`（本地存储）同步保存设置和会话，以直接复用现有同步状态模型；兼容用户脚本仍优先使用用户脚本存储接口。后端一经选择便保持不变，单次写入失败不会临时改用另一份旧数据。当前设置结构版本为 2，主要字段包括：

- `tabsEnabled`：分屏与页内帖子标签开关。
- `tabPresentation`：标签栏使用横向或垂直样式，默认横向。
- `verticalTabsAutoCollapse`：垂直标签栏是否自动收起，默认开启。
- `groupVerticalTabs`：垂直标签是否按内置主分类分组，默认关闭。
- `restoreSession`：是否在新的浏览器标签页中恢复最近一次阅读会话，默认关闭；不影响当前标签页刷新恢复。
- `colorizeTabs`：是否按帖子分类为标签添加半透明背景色，默认开启；关闭只影响显示。
- `layoutPreference`：自动、详情页在右或详情页在中间。
- `paneSizes`：单阅读区的侧栏宽度和列表所占比例。
- `dualPaneSizes`：双阅读区独立记忆的侧栏宽度和列表所占比例。
- `previewEnabled`、`previewClickMode`：预览开关和触发方式。
- `creditEnabled`：顶部 LDC 收入开关。
- `ownerOnlyEnabled`：帖子页只看楼主切换工具，按主题保存查看状态，默认关闭。
- `cleanModeEnabled`：清爽模式，隐藏公告、提示、分类徽章、标签和头像列，默认关闭。
- `lowEndOptimizationEnabled`：低端设备动画与过渡降级，默认关闭；只在设备满足低端判定时生效。
- `maxLiveFrames`：同时保留的活动内嵌页面数量，默认 3，范围 1 到 10。
- `maxOpenTabs`：阅读区标签总数上限，默认 50，范围 5 到 50。超出时按最久未活跃顺序淘汰非活动标签；该项没有设置界面入口。

从版本 1 迁移到版本 2 时，`restoreSession` 会被设为关闭，内部旧总开关会恢复为启用；此后版本 2 中用户明确选择的恢复状态会被保留。脚本是否运行由用户脚本管理器控制，设置界面不再暴露重复的总开关。

页面会话以 `sessionStorage`（会话存储）中的编号隔离，并在用户脚本存储中记录列表地址、列表滚动位置、布局比例、帖子标签、主阅读区活动标签、第二阅读区标签编号及其活动标签和各阅读位置。每个帖子标签只能属于一个阅读区；旧版会话缺少第二阅读区字段时自动迁移为空。活动归属记录会识别由浏览器复制出来的会话编号并立即换号，避免两个顶层标签页共同写入一份状态。

日常打开、关闭和切换帖子只更新当前浏览器标签页的会话，不更新共享恢复记录。同一标签页刷新时会继续加载自己的编号，与恢复开关无关。开启跨访问恢复后，`pagehide`（页面离开）先暂存关闭候选；相同编号随即重新启动会撤销候选，表示这只是刷新。真正关闭的多个页面只恢复最后关闭的一份状态，新访问领取后会删除共享记录，因此不同窗口的标签不会合并或被重复恢复。关闭恢复设置会立即清除共享候选和旧记录，会话索引最多保留 30 天并定期淘汰。首次直接请求帖子始终保持原生页面，也不会加载跨访问旧会话。

标签分类色只来自 `discourse/category.ts` 的固定主分类色表。标签根据帖子标题中的主分类名称查询常量颜色，不读取页面徽标样式、Open Graph（开放图谱）颜色元数据、iframe 消息或会话缓存；旧会话中残留的动态分类字段会在规范化时丢弃。启用分类上色时，非活动标签使用较低透明度；关闭时仅移除颜色表现。横向标签按可用空间等分收缩并保持一致，垂直标签可按同一固定主分类结果生成仅用于显示的分组，均只高亮当前标签。

标签拖拽继续使用浏览器原生拖动图像。拖动开始时只测量一次当前可拖动集合的位置，横向标签读取 X 轴、垂直标签读取 Y 轴；指针跨过相邻标签中心后才更新插入目标。避让动画只修改 `transform`（位移变换）和透明度，不重排 DOM（网页结构），放下时才提交并持久化最终顺序。分类分组模式只测量同组标签，避免跨分类改变帖子归属。动态效果减弱设置会把位移动画缩短为近乎即时。

垂直标签栏复用每个阅读区既有的标签根节点和操作容器，不创建第二份标签视图。收起状态只为正文保留一个字体相对尺寸的窄轨；展开层使用 `clip-path`（裁剪区域）和透明度覆盖当前阅读区，主内容网格列宽保持不变，因此不会改变 iframe（内嵌页面）宽度、触发正文重排或影响另一个阅读区。右键菜单和拖拽期间通过局部交互锁保持对应侧栏展开。

标签栏使用标签编号进行节点对照。标题、活动状态、分类色和辅助属性直接在已有节点上更新；只为新增标签创建节点、只移除已经关闭的节点，并仅在顺序确实改变时移动节点。事件处理器从标签栏当前状态读取回调和顺序，因此节点复用后不会保留旧回调或旧键盘索引。

## 6. 内嵌页面消息协议

消息只接受同源且来源窗口与受管理内嵌页面严格匹配的事件。主要类型如下：

| 消息 | 方向 | 用途 |
| --- | --- | --- |
| `ldu:frame-ready` | 内嵌页到顶层 | 报告已就绪、地址、标题和滚动状态 |
| `ldu:frame-state` | 内嵌页到顶层 | 报告地址或滚动变化 |
| `ldu:frame-interaction` | 帖子内嵌页到顶层 | 通知顶层关闭点击外部应收起的浮层 |
| `ldu:preview-config` | 顶层到内嵌页 | 下发预览开关和单击、双击模式 |
| `ldu:topic-tools-config` | 顶层到内嵌页 | 下发只看楼主、清爽模式和低端设备优化开关 |
| `ldu:bookmark` | 顶层到帖子内嵌页 | 携带主题编号，请求创建整篇主题书签 |
| `ldu:bookmark-result` | 帖子内嵌页到顶层 | 报告主题书签成功或论坛返回的失败原因 |
| `ldu:preview-open` | 内嵌页到顶层 | 请求顶层显示外链预览 |
| `ldu:preview-dismiss` | 内嵌页到顶层 | 请求关闭预览 |
| `ldu:topic-open` | 内嵌页到顶层 | 将另一个站内帖子作为新阅读标签打开 |
| `ldu:list-navigate` | 帖子页到顶层 | 将分类、用户页等非阅读链接交给列表页面 |
| `ldu:list-ready` | 列表页到顶层 | 报告列表页面就绪、网址和滚动状态 |
| `ldu:list-visual-ready` | 列表页到顶层 | 报告非加载占位的主内容已经渲染，可结束首次分屏视觉交接 |
| `ldu:list-state` | 列表页到顶层 | 节流报告列表网址、标题和滚动变化 |
| `ldu:list-interaction` | 列表页到顶层 | 通知顶层关闭点击外部应收起的浮层 |
| `ldu:list-topic-open` | 列表页到顶层 | 将列表中的帖子作为阅读标签打开 |
| `ldu:list-preview-open` | 列表页到顶层 | 请求顶层显示站外链接预览 |

预览配置采用握手机制：父页在页面加载时发送一次，内嵌页每次报告就绪后父页还会再次回送当前配置。这样可以覆盖脚本启动与页面加载顺序不同造成的时序缺口。

帖子命令由页面池排队：目标 iframe（内嵌页面）尚未就绪时先在后台创建而不切换当前标签，再保存在对应页面记录中，首次加载完成后只发送一次；标签关闭、暂停或页面池销毁时清除未发送命令。主题书签沿用 Discourse（论坛系统）当前原生请求：向 `/bookmarks.json` 提交 `bookmarkable_type=Topic`（书签类型为整篇主题）和稳定的主题编号，并携带页面自身的 CSRF（跨站请求伪造防护）令牌。它不再查找或回退点击任何楼层书签按钮，因此主楼不在当前渲染范围内也不会误收藏某一楼；论坛返回的成功或错误信息会显示在顶层页面。

预览单击/双击模式只有设置面板一个入口。上游预览工具栏中的重复切换按钮和独立存储路径已移除，面板修改后通过 `syncClickMode`（同步点击模式）立即更新当前预览控制器。

## 7. 链接预览与安全边界

顶层列表和内嵌帖子页分别拦截符合设置的普通左键事件。站内帖子链接交给标签系统；图片灯箱、按钮、表单控件、修饰键点击和当前帖子链接保持论坛原生行为。

预览核心直接移植 Link Hover Previewer 4.13.1。同源网页直接装入预览内嵌页，站外网页通过用户脚本跨域请求获取，再沿用上游的动态 HTML（网页源码）处理、加载令牌、内容桥、请求取消、预热和 LRU（最近最少使用）缓存逻辑。预览关闭时顶层只保留轻量控制器，不安装上游样式和事件监听；用户首次开启后才初始化一次，随后关闭会释放窗口、请求和缓存。

Linux Do 的 CSP（内容安全策略）包含 `base-uri 'none'`，站外源码写入 `srcdoc` 后会阻止上游插入的 `<base>` 生效。适配层因此在写入前将 `src`、`href`、`poster`、`action`、`formaction`、`srcset` 及 CSS（样式）中的相对地址解析为目标站绝对地址，避免脚本和样式被错误请求到 `linux.do`。

预览 iframe（内嵌页面）不设置 sandbox（沙箱）属性或其他运行权限限制。为了尽可能复现动态网页，目标页面脚本、同源能力和表单均可在预览环境中运行；设置页在预览开启时显示风险提示。预览缓存按条目数、估算内存和五分钟有效期管理，到期会主动清扫，关闭功能时会中止预热请求并释放缓存。

本项目只在上游模块外围增加适配：由顶层页面统一创建窗口；内嵌帖子通过既有消息桥请求打开；站内帖子继续进入阅读标签；图片灯箱、顶部导航和按钮保持论坛原生行为；新标签打开后关闭预览，并额外提供鼠标刷新按钮。

## 8. 阅读计数机制

阅读计数流程保留参考脚本的基本顺序：获取跨页面共享锁，发送 `/pageview`（页面浏览接口），检查论坛确认响应头，未确认时请求主题 JSON（结构化主题数据）兜底，再保存已确认或已受理状态。失败会释放锁并延迟重试，成功状态在八小时内去重。

页面滚动、楼层地址变化和标签切换不得触发内嵌页面重载或无限追踪。锁键通过带到期时间的小型索引回收；存储不可用时只在当前页面内存中去重。测试使用模拟请求，不应在真实论坛中手动重放计数接口。

## 9. LDC 收入请求

组件只在顶层页面创建，并放在语言切换按钮旁，避免每个帖子内嵌页重复显示。它先请求 Credit（积分）用户信息中的社区余额，再请求当前 Linux Do 用户的积分分数，两者差值作为收入参考值。默认每五分钟更新，用户点击可立即刷新。

插件跨域请求由 background service worker（后台服务工作线程）在 manifest（清单）权限范围内执行并携带登录态；同时刷新会合并，多页面优先复用一分钟内的共享快照，页面隐藏或功能关闭时停止后续调度。数据仅用于当前页面显示，不写入项目仓库或上传到其他服务。捐赠链接只由用户明确点击，插件不会自动访问支付地址。

## 10. 列表滚动与增量加载

列表 iframe（内嵌页面）使用自身文档的原生纵向滚动根，脚本不把 `#main-outlet`（主内容区）改成独立滚动容器，也不再创建顶层同步滚动条。这样 Discourse（论坛系统）的增量加载观察器仍在它预期的页面上下文中工作，不会因为父页面布局测量而持续误判列表底部可见。

列表页面以节流消息报告当前网址和滚动位置。只有就绪消息的网址与会话中保存的网址一致时才恢复滚动，避免从分类 A 导航到分类 B 时套用旧位置。由于 Discourse（论坛系统）会异步扩展列表和帖子高度，恢复过程会按实际滚动位置判断是否到达目标，在页面尚未撑开时继续尝试，达到目标或超过有限时窗后停止。标签跨阅读区前还会直接读取当前 iframe（内嵌页面）的网址和滚动状态，避免节流消息尚未送达时退回旧楼层。帖子页面拥有独立滚动根，列表和正文互不驱动对方的加载与滚动。

从尚未分屏的非阅读页首次打开帖子时，脚本会把当前顶层 `#main-outlet`（主内容区）临时移动到分屏列表区，保留原节点、事件和当前滚动位置。需要显示的帖子 iframe（内嵌页面）先创建，列表 iframe（内嵌页面）紧接着在同一执行周期启动，两者随后并行加载；刷新恢复、重新启用分屏和直接帖子转入分屏也遵循帖子优先的创建顺序。列表桥只有在主内容已经出现且不再只是加载占位时才发送视觉就绪消息；顶层随后把原节点放回原 DOM（网页结构）位置并显示列表 iframe（内嵌页面）。三秒兜底确保网络或页面结构异常时不会永久停在交接状态。视觉交接只用于首次用户点击，不参与刷新恢复或已经建立的分屏导航。

## 11. 测试与发布

自动化测试覆盖设置迁移、双阅读区会话归属、路由、直接帖子启动、列表与帖子页面桥接、标签状态、右键菜单、内嵌页面迁移与命令队列、生命周期释放、消息握手、预览、布局、阅读追踪、LDC 组件和完整构建。

版本遵循 Semantic Versioning（语义化版本）：仅修复兼容性问题时递增补丁号，例如 `0.2.0 → 0.2.1`；增加向后兼容功能时递增次版本号；发生不兼容变更时递增主版本号。版本只在 `package.json`（项目清单）维护，构建过程会自动写入油猴脚本头部，自动化测试会核对两者一致。每次修改都必须同时更新 `CHANGELOG.md`（更新日志）、重新构建并推送远端仓库，不允许只修改源码而保留旧构建产物。

发布前必须完成：

```powershell
pnpm test
pnpm check
pnpm build:all
pnpm package:extension
git diff --check
```

随后在已登录的真实论坛页面验证：首页、分类、用户页和搜索页在列表 iframe（内嵌页面）中独立导航；帖子 iframe（内嵌页面）身份与缓存保持不变；直接帖子进入分屏；刷新恢复；列表增量加载；新创建帖子标签的单击和双击预览；图片灯箱；设置条件显隐；以及两种桌面布局。验收过程不得发帖、点赞、支付或手动调用阅读计数接口。

## 12. 二次开发扩展点

- 新非阅读路由应加入 `discourse/routes.ts` 的路由识别，并验证它可以在列表 iframe（内嵌页面）中正常导航和滚动。
- 新标签状态应先扩展版本化类型和规范化函数，再修改存储；未知版本必须降级到安全默认值。
- 新内嵌页能力应通过现有消息桥增加明确消息类型，并同时校验角色、会话编号、来源窗口和来源域。
- 新跨域预览类型必须沿用设置页的风险提示和现有缓存释放规则，不得重新添加 iframe（内嵌页面）权限限制。
- 新顶部组件必须只在顶层创建，并考虑论坛导航重新渲染后重新挂载宿主。

## 13. 已知限制与排障

- 窄视口会回退论坛原生布局；这是避免正文和列表无法阅读的设计。
- 论坛页面结构调整可能导致挂载点失效，应先检查真实 DOM（网页结构）再更新选择器。
- 站外预览仍可能受目标站登录、跨域或页面自身策略影响，失败时可使用新标签打开。
- 内嵌帖子显示登录页时，先确认同一浏览器中的 Linux Do 登录态和同源内嵌权限。
- 分屏未出现时，检查“启用分屏模式”、视口宽度以及其他布局脚本是否冲突。
- 新帖子预览未生效时，先确认 `ldu:frame-ready` 后存在 `ldu:preview-config` 回包，再排查点击是否属于图片灯箱或按钮排除范围。
- 列表出现连续增量加载时，检查列表 iframe（内嵌页面）内部的 `html/body`（页面根节点）是否仍为原生滚动根，父外壳不得代理其滚动。
