# V0.4 Browser Extension Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将现有 V0.2 稳定用户脚本迁移为 Chrome Manifest V3 浏览器插件，同时让完整宿主代码不再进入子 iframe，并让预览核心只在首次启用时加载。

**Architecture:** 保留现有 `LinuxDoApp`、布局、标签、会话、阅读计数、列表和帖子 frame 协议。新增独立的 host、bridge、preview runtime 与 background 构建入口：host 只运行于顶层页面，bridge 只承载既有 frame 协议，preview runtime 由 host 首次需要时动态导入，background 为上游预览和 LDC 请求提供兼容的跨域请求通道。V0.2 用户脚本产物继续构建和测试，作为行为回归基线。

**Tech Stack:** TypeScript、esbuild、Chrome Manifest V3、Vitest、jsdom。

---

### Task 1: Preserve the stable userscript while making preview injectable

**Files:**
- Modify: `src/preview/upstream-preview-controller.ts`
- Modify: `src/app.ts`
- Modify: `src/main.ts`
- Test: `tests/upstream-preview.test.ts`

1. 为 `PreviewController` 增加安装器加载函数，不再静态导入上游预览核心。
2. 用失败测试覆盖延迟安装、首次 frame 预览等待加载及关闭状态不加载。
3. 在用户脚本入口静态提供原安装器，保持现有单文件行为不变。
4. 运行预览和应用启动测试。
5. 提交独立兼容性改造。

### Task 2: Add extension runtime entries

**Files:**
- Create: `src/extension/host.ts`
- Create: `src/extension/bridge.ts`
- Create: `src/extension/preview-runtime.ts`
- Create: `src/extension/background.ts`
- Create: `src/extension/request-client.ts`
- Test: `tests/extension-request.test.ts`

1. host 顶层入口启动现有应用，并通过 `chrome.runtime.getURL` 延迟导入 preview runtime。
2. bridge 入口仅调用现有 `bootFrameBridge`，保持 frame name 和消息协议不变。
3. background 使用扩展权限执行跨域请求，并返回上游兼容响应。
4. request client 安装最小 GM 请求兼容层，支持回调、超时和 abort。
5. 用单元测试覆盖成功、错误、超时和取消行为。
6. 提交运行时入口。

### Task 3: Build four isolated extension artifacts

**Files:**
- Create: `extension/manifest.json`
- Create: `scripts/build-extension.ts`
- Modify: `package.json`
- Test: `tests/extension-build.test.ts`

1. 构建 `host.js`、`bridge.js`、`preview-runtime.js`、`background.js` 四个独立产物。
2. host content script 设置 `all_frames: false`，bridge 设置 `all_frames: true`。
3. preview runtime 作为 web accessible resource，仅匹配 Linux.do。
4. background 配置必要的跨域 host permissions，不修改网页 CSP。
5. 测试 manifest、入口隔离、host 不包含上游预览源码以及 bridge 不包含宿主 UI。
6. 提交构建和 manifest。
