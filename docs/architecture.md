# 架构说明

## 设计原则

1. 帖子正文继续由 Discourse（论坛系统）负责渲染和交互。
2. 用户脚本只负责布局、导航编排和状态协调，不重写论坛客户端。
3. 持久化用户意图和阅读状态，不保存网页节点。
4. 可选功能彼此独立，关闭某一项不应破坏其他功能。
5. 预览以网页兼容性为优先，会运行目标脚本并开放同源能力；风险必须明确提示且功能默认关闭。
6. 任一模块失败时优先恢复原生导航，而不是阻断社区页面。

## 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `core`（核心） | 设置、会话结构、迁移和存储适配 | 网页选择器、网络追踪 |
| `discourse`（论坛适配） | 路由识别、帖子编号、阅读追踪 | 界面布局 |
| `tabs`（标签） | 标签状态和活动内嵌页面预算 | 设置界面 |
| `ui`（界面） | 分屏、标签栏、拖动宽度、统一图标、设置面板 | 存储实现 |
| `preview`（预览） | 链接策略、上游动态运行时、缓存和悬浮窗 | 阅读计数 |

## 页面结构

分屏启用后，脚本在 `body`（页面主体）下挂载稳定的 `#ldu-layout-shell`（分屏外壳）。顶层页面只保留导航条、侧栏、设置和 LDC 收入组件；论坛原有主内容区在分屏期间隐藏，不再承担列表导航。

外壳内包含互相独立的同源 iframe（内嵌页面）上下文：一个列表页面只负责主页、分类、用户页、搜索等非阅读内容；主帖子页面池负责默认阅读标签；用户通过标签右键菜单开启后，第二帖子页面池负责新的并排阅读区。列表导航不会销毁帖子页面，任一阅读区的帖子跳转和刷新也不会重载列表或另一个阅读区。默认三分屏顺序为“侧栏、帖子、非阅读页”，默认二分屏顺序为“侧栏、非阅读页、帖子”；开启第二阅读区后，两块阅读区域平分原正文份额。

顶层文档在 `document-start`（文档开始解析）阶段先判断当前浏览器标签页是否存在分屏会话，存在时立即加入最小遮蔽样式；`body`（页面主体）出现后启动完整应用并创建列表、主阅读区和第二阅读区框架。用户脚本不在 iframe（内嵌页面）中重复解析，父页面在每个同源页面加载后安装一次轻量桥和角色样式。内嵌页在安装完成前保持隐藏，因此不会先显示自身顶栏、侧栏或加载标志再跳动。

顶层导航和侧栏中的站内非帖子链接会转发给列表页面；列表中的帖子链接会转发给帖子标签系统；阅读页中的其他帖子链接打开新标签，分类和用户页等链接则转发给列表页面。消息同时校验来源域、真实来源窗口、受管理角色编号和帖子身份；导航消息只有在父页确认成功后才保持拦截，否则超时回退论坛原生点击。附件、图片、下载和新标签目标不进入列表区。

## 状态模型

设置与页面会话分开保存，均带结构版本。用户拖动的侧栏宽度和正文/列表比例同时写入长期设置；会话按浏览器标签页隔离，记录列表 iframe（内嵌页面）的网址与滚动、布局宽度、全部帖子标签、两个阅读区的标签归属和活动标签、帖子网址及阅读位置。同一标签编号不得同时出现在两个阅读区。

损坏或未知版本会回退默认值，不影响论坛加载。高频滚动只节流写入，`pagehide`（页面离开）事件执行最后一次同步保存。会话和阅读锁均维护索引并按过期时间回收；页面长期打开时低频重复维护，真正离开后取消维护任务。关闭标签页后，其会话不会被其他页面主动读取；同一标签页暂时离站再返回时仍可沿用自己的会话标识，不可达的旧记录在 30 天后统一回收。存储失败会退化为内存状态并在页面显示一次提示。

## 内嵌页面生命周期

列表 iframe（内嵌页面）始终只有一个，由专用控制器负责创建、导航、恢复滚动和销毁。两个帖子页面池共享一个全局活动额度；超出后先移除两个阅读区中最久未使用的非活动页面，再更新标签为暂停状态。标签移动到第二阅读区前会同步读取其当前网址和滚动位置，再转移页面记录与 iframe（内嵌页面）；已加载页面保持就绪，命令不会因移动而滞留。真正重载或重建页面时只在匹配网址的就绪消息后恢复一次滚动，不用循环滚动驱动异步内容。

显式点击同一帖子的其他楼层时，已有内嵌页面会导航到新目标；单纯滚动引起的楼层 URL（网址）更新不会重设 iframe（内嵌页面）。标签拖拽只在放下时重排所属阅读区的编号顺序，不重建页面实例。关闭分屏或关闭最后一个阅读标签时销毁两类 iframe（内嵌页面）运行时，但会话数据仍保留，重新启用可按状态重建。

## 阅读计数不变量

流程严格沿用参考脚本：

1. 为帖子获取跨标签页共享锁。
2. 使用稳定的刷新会话追踪编号发送 `/pageview`（页面浏览接口）。
3. 读取 `x-discourse-trackview` 或 `x-discourse-browserpageview`（论坛确认响应头）。
4. 未确认时请求主题 JSON（结构化主题数据）作为兜底。
5. 已确认或已受理状态保存八小时；完全失败会释放锁并延迟重试。

界面切换本身不会重复产生追踪请求。测试只使用模拟响应，不向实站手动发送追踪请求。

## 预览安全不变量

预览功能沿用上游工具的动态页面加载能力。站外内容只在用户主动触发后获取，预览 iframe（内嵌页面）不设置 sandbox（沙箱），目标网页脚本可完整运行，也可能获得 Linux Do 同源能力，因此设置面板会明确提示账号数据风险。适配层会按重定向后的最终网址修正相对资源，排除下载和常见二进制预热，在传输中及响应完成后限制单响应体积，并在缓存每次增大后立即执行容量淘汰。

## 容错

- 存储不可用：使用默认值或内存状态，论坛仍可访问。
- 页面结构暂未出现：等待 Discourse（论坛系统）后续 DOM（网页结构）变化再次同步，不创建半成品外壳。
- 布局不支持：低于断点自动恢复原生页面。
- 列表内嵌页面失效：保留当前帖子标签，重新进入分屏时重建列表上下文。
- 内嵌页面超限：暂停非活动页面而不丢失标签。
- 阅读追踪失败：释放锁并延迟重试，不阻塞阅读。
- 预览失败：显示失败状态并保留新标签打开入口。
