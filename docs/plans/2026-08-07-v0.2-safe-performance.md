# v0.2 Safe Performance Optimizations Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Reduce avoidable allocations, DOM work, and repeated metadata parsing without changing split routing, iframe lifecycles, preview loading, or view-count behavior.

**Architecture:** Keep the existing v0.2 host page plus managed iframe architecture. Make only local optimizations: reuse the active-frame identity, add direct tab lookup, and skip topic metadata scans for mutations that cannot affect metadata. Preserve all existing public behavior and add focused regression tests.

**Tech Stack:** TypeScript（类型脚本语言）, Vitest（测试框架）, jsdom（浏览器环境模拟器）, pnpm（包管理器）.

---

### Task 1: Avoid redundant frame activation work

**Files:**
- Modify: `src/tabs/frame-pool.ts`
- Test: `tests/frame-pool.test.ts`

**Step 1: Add a regression test**

Verify that activating the already-active frame does not rewrite its accessibility attributes, while switching frames still updates the old and new frame.

**Step 2: Implement the minimal change**

Track the active tab ID inside each pool. Only toggle `aria-hidden` and `tabIndex` when the active ID changes. Keep overflow suspension behavior unchanged.

**Step 3: Run the focused test**

Run `pnpm test -- tests/frame-pool.test.ts` and expect all frame-pool tests to pass.

### Task 2: Add direct tab lookup to avoid full tab-array copies

**Files:**
- Modify: `src/tabs/tab-store.ts`
- Modify: `src/app.ts`
- Test: `tests/tab-store.test.ts`

**Step 1: Add a regression test**

Verify that looking up an existing and missing tab returns the expected snapshot or `null`.

**Step 2: Implement the minimal change**

Add a `get(tabId)` method that clones only the matching tab. Replace single-tab `getTabs().find(...)` call sites in the app with this method. Keep list getters defensive and unchanged.

**Step 3: Run the focused tests**

Run `pnpm test -- tests/tab-store.test.ts tests/frame-pool.test.ts` and expect all tests to pass.

### Task 3: Reduce repeated topic metadata parsing

**Files:**
- Modify: `src/frame-bridge.ts`
- Test: `tests/frame-bridge.test.ts`

**Step 1: Add a regression test**

Verify that metadata is still discovered when a topic category or Open Graph（开放图谱）metadata node is inserted, while unrelated post-body mutations do not change the reported category state.

**Step 2: Implement the minimal change**

Gate the topic MutationObserver（网页变化监听器）metadata read behind a small relevance check for `head`, title, topic-title, topic-category, or nodes containing the relevant metadata selectors. Keep URL and title reporting behavior intact.

**Step 3: Run focused bridge tests**

Run `pnpm test -- tests/frame-bridge.test.ts` and expect all bridge tests to pass.
