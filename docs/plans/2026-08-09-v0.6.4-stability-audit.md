# v0.6.4 Stability Audit Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复宿主通知菜单导航、只看楼主与热门回复组合、429 自动过盾，并确认独立工具不受分屏开关控制。

**Architecture:** 保持 v0.6.3 的宿主、轻量 iframe loader（内嵌页加载器）和 lazy runtime（按需运行模块）边界不变。宿主只增加一个明确的用户菜单导航分支；只看楼主仍在按需模块中工作，但楼主身份从当前主题预加载元数据或帖子标记读取，并只处理当前重建或新增的帖子节点；Challenge（验证）脚本保持独立注入。

**Tech Stack:** TypeScript、Vitest、JSDOM、esbuild、Chrome/Firefox Manifest V3（扩展清单第三版）。

---

### Task 1: 锁定通知菜单导航规则

**Files:**
- Modify: `src/app.ts`
- Test: `tests/browser/smoke.test.ts`

1. 增加失败测试：通知条目应打开阅读标签并关闭浮层；“查看所有通知”应导航列表 iframe，而不是改变隐藏宿主页路由。
2. 在通用 `.btn` 排除规则之前识别 `.user-menu` 内的导航链接，同时保留用户菜单页签的论坛原生行为。
3. 抽取并复用现有页面外点击关闭动作，避免维护两套浮层关闭机制。
4. 运行定向测试，确认帖子链接与普通列表链接仍遵循原分屏规则。

### Task 2: 重建只看楼主的稳定数据流

**Files:**
- Modify: `src/discourse/topic-tools.ts`
- Test: `tests/topic-tools.test.ts`

1. 增加失败测试：从长帖中部进入、主楼不在 DOM（文档对象模型）时，仍能从 `#data-preloaded` 读取 `created_by.id`（发帖人编号）。
2. 增加失败测试：只看楼主与论坛热门回复重建后的帖子流可叠加；新增节点只做增量过滤。
3. 增加失败测试：按钮只挂载到 `.timeline-footer-controls`，插入热门回复按钮之前，文案始终为“只看楼主”，活动状态使用论坛原生蓝色按钮类。
4. 楼主身份优先从页面已有帖子标记读取，必要时从匹配当前主题的预加载元数据定向提取，不发额外网络请求。
5. 移除正文底部等回退挂载点；时间轴未就绪时等待现有增量监听再次同步。
6. 保留 v0.6.3 的按需加载、单 Observer（页面监听器）、rAF（动画帧）合并和冻结暂停逻辑。

### Task 4: 覆盖 429 并阻止明显跳转循环

**Files:**
- Modify: `src/discourse/challenge-bypass.ts`
- Test: `tests/challenge-bypass.test.ts`

1. 增加失败测试：`.dialog-body` 中的 `429 error` 会进入 Challenge（验证）页面。
2. 增加失败测试：同一页面短时间重复出现同一失败弹窗时不再次跳转。
3. 将防重复状态限定在当前浏览器标签页的 `sessionStorage`（会话存储）中，只保存当前 URL（统一资源定位符）与时间戳。
4. 保持所有 iframe 独立注入，不依赖分屏设置。
