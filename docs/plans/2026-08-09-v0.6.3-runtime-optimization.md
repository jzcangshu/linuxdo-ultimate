# Linux Do Ultimate v0.6.3 Runtime Optimization Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让默认关闭的页面工具接近零加载、零监听成本，修复只看楼主的热循环和 SPA 状态问题，并减少所有页面层级的扩展脚本解析量。

**Architecture:** 保留现有 host / frame / challenge / preview 职责，不引入全局 DOM 协调器或全局 iframe 预算。`bridge.js` 只做 frame 识别和关键首屏隐藏，真正桥接逻辑按需加载；清爽与低端模式只切换根节点状态，只看楼主作为唯一需要 DOM 增量监听的懒加载运行时。

**Tech Stack:** TypeScript、esbuild、Chrome/Firefox Manifest V3、Vitest、jsdom。

### 明确不在本轮执行

- 不引入全局 `DomMutationCoordinator`；各 Observer 职责和生命周期不同，集中化会扩大改动面。
- 不把两个 `TopicFramePool` 改成共享预算；这会改变用户配置语义并减少正常功能可用资源。
- 不拆分设置面板、标签布局、阅读计数或 challenge；当前收益不足以覆盖回归风险。
- 不把 owner、clean、low-end 各自拆成独立大模块；只有 owner 需要懒加载运行时，clean 和 low-end 保持轻量状态切换。
