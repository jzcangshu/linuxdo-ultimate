# 架构说明

## 设计原则

1. 帖子正文继续由 Discourse（论坛系统）负责渲染和交互。
2. 用户脚本只负责布局、导航编排和状态协调，不重写论坛客户端。
3. 持久化用户意图和阅读状态，不保存网页节点。
4. 可选功能彼此独立，关闭某一项不应破坏其他功能。
5. 站外获取的脚本永远不能在 Linux.do 来源中执行。
6. 任一模块失败时优先恢复原生导航，而不是阻断社区页面。

## 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `core`（核心） | 设置、会话结构、迁移和存储适配 | 网页选择器、网络追踪 |
| `discourse`（论坛适配） | 路由识别、帖子编号、阅读追踪 | 界面布局 |
| `tabs`（标签） | 标签状态和活动内嵌页面预算 | 设置界面 |
| `ui`（界面） | 分屏、标签栏、拖动宽度、设置面板 | 存储实现 |
| `preview`（预览） | 链接策略、内容清理、缓存和悬浮窗 | 阅读计数 |

## 页面结构

顶层 Linux.do 页面始终保留为列表和导航宿主。脚本在 `#main-outlet-wrapper`（主内容容器）中挂载一个帖子阅读区，不永久移动或复制 Discourse（论坛系统）持有的节点。

帖子标签使用同源 iframe（内嵌页面）加载真实帖子，因此正文、投票、反应、回复编辑器和站内导航继续使用论坛原生实现。三分屏顺序为“侧栏、帖子、列表”，二分屏顺序为“侧栏、列表、帖子”。

## 状态模型

设置与页面会话分开保存，均带结构版本。用户拖动的侧栏宽度和正文/列表比例同时写入长期设置；会话按浏览器标签页隔离，记录列表网址、列表滚动、布局宽度、标签、活动标签、帖子网址和阅读位置。

损坏或未知版本会回退默认值，不影响论坛加载。高频滚动只节流写入，`pagehide`（页面离开）事件执行最后一次同步保存。

## 内嵌页面生命周期

活动 iframe（内嵌页面）数量有上限。超出后先移除最近最少使用的非活动页面，再更新标签为暂停状态，避免状态回调重入。重新激活时按保存的网址创建页面并恢复滚动位置。

显式点击同一帖子的其他楼层时，已有内嵌页面会导航到新目标；单纯滚动引起的楼层 URL（网址）更新不会重设 iframe（内嵌页面）。批量关闭只产生一次状态通知，避免标签栏重复渲染。

## 阅读计数不变量

流程严格沿用参考脚本：

1. 为帖子获取跨标签页共享锁。
2. 使用稳定的刷新会话追踪编号发送 `/pageview`（页面浏览接口）。
3. 读取 `x-discourse-trackview` 或 `x-discourse-browserpageview`（论坛确认响应头）。
4. 未确认时请求主题 JSON（结构化主题数据）作为兜底。
5. 已确认或已受理状态保存八小时；完全失败会释放锁并延迟重试。

界面切换本身不会重复产生追踪请求。测试只使用模拟响应，不向实站手动发送追踪请求。

## 预览安全不变量

Linux.do 同源页面可以交互式显示。站外页面只在用户启用并触发预览后获取，随后转成无脚本静态内容，并放入空权限 sandbox（沙箱）。

清理器删除脚本、表单、框架、事件属性、刷新指令、危险协议和主动媒体。缓存同时限制条目数、总体积和有效时间，请求可中止，避免内存与网络资源失控。

## 容错

- 存储不可用：使用默认值或内存状态，论坛仍可访问。
- 页面结构暂未出现：等待 Discourse（论坛系统）后续 DOM（网页结构）变化再次同步。
- 布局不支持：低于断点自动恢复原生页面。
- 内嵌页面超限：暂停非活动页面而不丢失标签。
- 阅读追踪失败：释放锁并延迟重试，不阻塞阅读。
- 预览失败：显示失败状态并保留新标签打开入口。
