# Linux Do 社区终极优化脚本技术维护文档

本文面向后续维护者和二次开发者。普通用户请先阅读项目根目录的 `README.md`。

## 1. 技术栈与构建产物

源码使用 TypeScript（类型脚本语言），测试使用 Vitest（测试框架）与 jsdom（浏览器环境模拟器），构建使用 esbuild（打包工具）。入口为 `src/main.ts`，构建脚本将全部模块打包为单个 `dist/linuxdo-ultimate.user.js` 用户脚本。

```powershell
pnpm install
pnpm test
pnpm check
pnpm build
```

`package.json` 中的版本号会写入用户脚本头。发布前还应运行 `git diff --check` 检查空白和补丁格式。

## 2. 模块职责

| 目录或文件 | 职责 |
| --- | --- |
| `src/app.ts` | 顶层页面编排、路由同步、设置应用、各模块协调 |
| `src/core` | 设置、会话结构、默认值、迁移和存储适配 |
| `src/discourse` | 路由识别、直接帖子交接、阅读计数追踪 |
| `src/tabs` | 帖子标签、内嵌页面池和标签栏渲染 |
| `src/ui` | 分屏布局、拖动比例、设置面板和全局样式 |
| `src/preview` | 悬浮预览、跨域获取、缓存和内容清理 |
| `src/frame-bridge.ts` | 内嵌帖子页与顶层页面之间的事件桥 |
| `src/credit` | 顶部 LDC 收入组件和数据请求 |

模块原则是让 Discourse（论坛系统）继续负责帖子正文、回复、投票、反应和时间线，脚本只负责页面编排与状态协调，不复制论坛业务逻辑。

## 3. 顶层页面与内嵌帖子页

分屏开启时，顶层页面保留真实话题列表和侧栏。`LayoutController`（布局控制器）在主容器中加入帖子面板，`TopicFramePool`（帖子页面池）为每个活动标签创建同源 iframe（内嵌页面）。

内嵌页由 `frame-bridge.ts` 标记为嵌入状态，样式会隐藏其顶部导航和侧栏，但保留正文、时间线及帖子操作控件。活动页数量超过设置上限时，页面池按最近最少使用顺序暂停非活动页面；标签状态和地址仍保留，重新激活时再创建页面并恢复滚动位置。

## 4. 路由与直接帖子启动

列表、分类、标签、搜索和书签等可承载真实列表的路由直接挂载分屏。新的浏览器标签页直接进入帖子 A 时保持论坛原生阅读页，不自动改变布局。只有用户随后主动点击站内入口时才建立短期交接：

1. 点击另一个帖子 B 时，以论坛主页作为列表，交接记录依次保存 A、B；进入分屏后 B 为活动标签。
2. 点击分类、主页或搜索页时，以目标页面作为列表，交接记录保存 A。
3. 同帖楼层、用户页、聊天、站外链接及带修饰键的点击不建立交接。
4. 交接记录写入 `sessionStorage`（会话存储），有效期为 15 秒，并在真实列表容器挂载成功后只消费一次。

若当前浏览器标签页本来已有分屏会话，顶层意外进入帖子路由时会把该帖加入当前会话并返回原列表。交接记录严格校验有效期、来源域名、列表路径和帖子路径；存储不可用时保留论坛原生导航。

## 5. 设置与会话存储

长期设置通过用户脚本存储接口保存，接口不可用时回退到 `localStorage`（本地存储）。当前设置结构版本为 2，主要字段包括：

- `tabsEnabled`：分屏与页内帖子标签开关。
- `restoreSession`：是否在新的浏览器标签页中恢复最近一次阅读会话，默认关闭；不影响当前标签页刷新恢复。
- `colorizeTabs`：是否按帖子分类为标签添加半透明背景色，默认开启；关闭只影响显示，不清除已缓存的分类信息。
- `layoutPreference`：自动、详情页在右或详情页在中间。
- `paneSizes`：侧栏宽度和列表所占比例。
- `previewEnabled`、`previewClickMode`：预览开关和触发方式。
- `creditEnabled`：顶部 LDC 收入开关。
- `maxLiveFrames`：同时保留的活动内嵌页面数量，上限 10。

从版本 1 迁移到版本 2 时，`restoreSession` 会被设为关闭，内部旧总开关会恢复为启用；此后版本 2 中用户明确选择的恢复状态会被保留。脚本是否运行由用户脚本管理器控制，设置界面不再暴露重复的总开关。

页面会话以 `sessionStorage`（会话存储）中的编号隔离，并在用户脚本存储中记录列表地址、列表滚动位置、布局比例、帖子标签、活动标签和各阅读位置。活动归属记录会识别由浏览器复制出来的会话编号并立即换号，避免两个顶层标签页共同写入一份状态。

日常打开、关闭和切换帖子只更新当前浏览器标签页的会话，不更新共享恢复记录。同一标签页刷新时会继续加载自己的编号，与恢复开关无关。开启跨访问恢复后，`pagehide`（页面离开）先暂存关闭候选；相同编号随即重新启动会撤销候选，表示这只是刷新。真正关闭的多个页面只保留最后关闭的一份状态，新访问领取后会删除共享记录，因此不同窗口的标签不会合并或被重复恢复。关闭恢复设置会立即清除共享候选和旧记录。首次直接请求帖子始终保持原生页面，也不会加载跨访问旧会话。

标签分类色不保存固定色表。点击话题列表时会直接读取所在行的分类徽标；内嵌帖子加载后还会从正文顶部的分类徽标校准，并把分类名和颜色写入会话。这样新标签无需等待完整页面加载，页面池暂停、重建或刷新后也能立即复用颜色。启用分类上色时，非活动标签使用较低透明度；关闭时仅移除颜色表现。所有标签按可用空间等分收缩并保持一致，只有当前标签显示底部高亮条。

## 6. 内嵌页面消息协议

消息只接受同源且来源窗口与受管理内嵌页面严格匹配的事件。主要类型如下：

| 消息 | 方向 | 用途 |
| --- | --- | --- |
| `ldu:frame-ready` | 内嵌页到顶层 | 报告已就绪、地址、标题和滚动状态 |
| `ldu:frame-state` | 内嵌页到顶层 | 报告地址或滚动变化 |
| `ldu:preview-config` | 顶层到内嵌页 | 下发预览开关和单击、双击模式 |
| `ldu:preview-open` | 内嵌页到顶层 | 请求顶层显示外链预览 |
| `ldu:preview-dismiss` | 内嵌页到顶层 | 请求关闭预览 |
| `ldu:topic-open` | 内嵌页到顶层 | 将另一个站内帖子作为新阅读标签打开 |

预览配置采用握手机制：父页在页面加载时发送一次，内嵌页每次报告就绪后父页还会再次回送当前配置。这样可以覆盖脚本启动与页面加载顺序不同造成的时序缺口。

预览单击/双击模式只有设置面板一个入口。上游预览工具栏中的重复切换按钮和独立存储路径已移除，面板修改后通过 `syncClickMode`（同步点击模式）立即更新当前预览控制器。

## 7. 链接预览与安全边界

顶层列表和内嵌帖子页分别拦截符合设置的普通左键事件。站内帖子链接交给标签系统；图片灯箱、按钮、表单控件、修饰键点击和当前帖子链接保持论坛原生行为。

预览核心直接移植 Link Hover Previewer 4.12.2。同源网页直接装入预览内嵌页，站外网页通过用户脚本跨域请求获取，再沿用上游的动态 HTML（网页源码）处理、加载令牌、内容桥、请求取消、预热和 LRU（最近最少使用）缓存逻辑。

Linux Do 的 CSP（内容安全策略）包含 `base-uri 'none'`，站外源码写入 `srcdoc` 后会阻止上游插入的 `<base>` 生效。适配层因此在写入前将 `src`、`href`、`poster`、`action`、`formaction`、`srcset` 及 CSS（样式）中的相对地址解析为目标站绝对地址，避免脚本和样式被错误请求到 `linux.do`。

预览 iframe（内嵌页面）在加入页面前即设置上游同款 `allow-scripts allow-same-origin allow-forms` 沙箱与加载名称。为了复现动态网页，目标页面脚本会在预览环境中运行；设置页在预览开启时显示风险提示。

本项目只在上游模块外围增加适配：由顶层页面统一创建窗口；内嵌帖子通过既有消息桥请求打开；站内帖子继续进入阅读标签；图片灯箱、顶部导航和按钮保持论坛原生行为；新标签打开后关闭预览，并额外提供鼠标刷新按钮。

## 8. 阅读计数机制

阅读计数流程保留参考脚本的基本顺序：获取跨页面共享锁，发送 `/pageview`（页面浏览接口），检查论坛确认响应头，未确认时请求主题 JSON（结构化主题数据）兜底，再保存已确认或已受理状态。失败会释放锁并延迟重试，成功状态在八小时内去重。

页面滚动、楼层地址变化和标签切换不得触发内嵌页面重载或无限追踪。测试使用模拟请求，不应在真实论坛中手动重放计数接口。

## 9. LDC 收入请求

组件只在顶层页面创建，并放在语言切换按钮旁，避免每个帖子内嵌页重复显示。它先请求 Credit（积分）用户信息中的社区余额，再请求当前 Linux Do 用户的积分分数，两者差值作为收入参考值。默认每五分钟更新，用户点击可立即刷新。

跨域请求使用用户脚本请求能力并携带登录态；数据仅用于当前页面显示，不写入项目仓库或上传到其他服务。捐赠链接只由用户明确点击，脚本不会自动访问支付地址。

## 10. 列表滚动与增量加载

真实话题列表继续使用浏览器页面作为纵向滚动根，不能把 `#main-outlet` 改成独立滚动容器，否则 Discourse（论坛系统）的增量加载观察器可能持续判定列表底部可见，形成无限请求。

详情页在右时，浏览器原生滚动条被视觉隐藏，并在列表边缘显示同步滚动条；它只映射页面现有滚动范围，不创建第二套内容加载逻辑。帖子面板使用吸顶定位和固定视口高度，内嵌页自身独立滚动到底部，不在阅读区保留写死的底部空间。

## 11. 测试与发布

自动化测试覆盖设置迁移、会话、路由、直接帖子交接、标签状态、内嵌页面池、消息握手、预览清理、布局、滚动条、阅读追踪、LDC 组件和完整构建。

发布前必须完成：

```powershell
pnpm test
pnpm check
pnpm build
git diff --check
```

随后在已登录的真实论坛页面验证：首页和分类列表打开帖子、从用户页进入帖子、直接地址进入帖子、恢复开关的两种状态、新创建帖子标签的单击和双击预览、图片灯箱、设置条件显隐及桌面宽度下的布局。验收过程不得发帖、点赞、支付或手动调用阅读计数接口。

## 12. 二次开发扩展点

- 新列表路由应加入 `discourse/routes.ts` 的路由识别，并验证其真实页面含有可挂载的列表结构。
- 新标签状态应先扩展版本化类型和规范化函数，再修改存储；未知版本必须降级到安全默认值。
- 新内嵌页能力应通过现有消息桥增加明确消息类型，并同时校验来源窗口和来源域。
- 新跨域预览类型必须先定义内容类型和安全策略，不可直接执行目标站脚本。
- 新顶部组件必须只在顶层创建，并考虑论坛导航重新渲染后重新挂载宿主。

## 13. 已知限制与排障

- 窄视口会回退论坛原生布局；这是避免正文和列表无法阅读的设计。
- 论坛页面结构调整可能导致挂载点失效，应先检查真实 DOM（网页结构）再更新选择器。
- 站外预览无法还原依赖脚本运行的页面，可使用新标签打开。
- 内嵌帖子显示登录页时，先确认同一浏览器中的 Linux Do 登录态和同源内嵌权限。
- 分屏未出现时，检查“启用分屏模式”、视口宽度以及其他布局脚本是否冲突。
- 新帖子预览未生效时，先确认 `ldu:frame-ready` 后存在 `ldu:preview-config` 回包，再排查点击是否属于图片灯箱或按钮排除范围。
- 列表出现连续增量加载时，检查页面滚动根是否仍为浏览器页面，主列表容器不得设置独立纵向滚动。
