# 测试说明

## 1. 自动化检查

在项目根目录依次运行：

```powershell
pnpm test
pnpm check
pnpm build
git diff --check
```

`pnpm test` 会在执行构建产物测试时重新生成用户脚本，避免把旧版 `dist`（发布目录）误判为当前源码结果。自动化覆盖如下：

| 范围 | 主要检查 |
| --- | --- |
| 设置与存储 | 迁移、条件选项、单次持久化、容量异常降级、会话索引、定时维护和页面离开释放 |
| 路由与启动 | 首页、分类、标签、搜索、用户、书签、直接帖子、刷新恢复 |
| 内嵌页桥接 | 顶层完整应用唯一启动、父页单次安装、来源窗口与主题校验、导航确认和原生回退 |
| 标签与资源 | 无限标签状态、双阅读区归属、拖拽排序单次提交、共享活动额度、最近最少使用暂停、分类色缓存 |
| 图标与菜单 | 统一画布、线宽和无障碍属性；右键菜单每项拥有对应图标 |
| 预览 | 按需安装与卸载、完整脚本权限、重定向资源、下载/二进制排除、8 MiB 响应中止、缓存到期与运行环境释放 |
| 阅读计数 | 锁所有权、接口顺序、确认响应头、主题 JSON（结构化主题数据）兜底、过期回收和存储异常 |
| LDC 收入 | 两接口一致性、后台暂停、请求复用、跨页面锁、网络中止、坏缓存与过期缓存移除 |
| 构建 | 版本一致、`@noframes`（不在内嵌页运行）、单文件安装产物和压缩输出 |

`tests/browser/smoke.test.ts` 是 jsdom（浏览器结构模拟器）中的 DOM（网页结构）集成冒烟测试，不是 Chrome（谷歌浏览器）真实网页测试，不能据此宣称实站功能已通过。

## 2. 本地界面夹具

运行：

```powershell
node scripts/serve-fixtures.mjs
```

打开 `http://127.0.0.1:4173/latest`，验证分屏外壳、标签栏、设置面板、拖动比例和内容高度。夹具只用于稳定复现界面结构，论坛路由、增量加载、登录态和第三方网页预览必须在真实 Linux Do 页面验证。

临界宽度回退策略是本轮唯一明确不处理的审计项；不要把不适合分屏的窄视口问题混入其他功能验收。

## 3. 真实 Chrome 验收

使用已登录且实际连接类型为 `extension`（官方 Chrome 扩展实例）的浏览器，只做只读检查。不得发帖、点赞、支付、创建书签，也不得通过开发工具手动重放阅读计数接口。

| 场景 | 验收重点 |
| --- | --- |
| 首页与分类 | 进入分屏、侧栏导航留在非阅读区、列表正常增量加载且不会连续请求 |
| 搜索、用户、书签、标签页 | 非阅读区独立导航，阅读区不刷新、不丢缓存 |
| 首次直接帖子 | 保持论坛原生页面；主动点击下一站内链接后才进入分屏并保留当前帖子 |
| 浏览器刷新 | 已有分屏在刷新后恢复；关闭浏览器标签后不会被其他窗口错误拾取 |
| 分屏首屏 | 原生单列内容不闪现；三个框架同轮创建；阅读区从首次绘制起不显示自身加载标志、顶栏或侧栏 |
| 多帖子与第二阅读区 | 标签切换、关闭、拖拽排序、右键移动、滚动进度继承、关闭第二阅读区后归并 |
| 布局与高度 | 列表和帖子滚动条都延伸到底部；收起侧栏后保持用户比例；阅读区无底部空白 |
| 标签表现 | 分类色在已有信息时立即显示，暂停重建后复用；活动标签底部高亮；宽度等分收缩；拖动插入标记清晰且排序后活动页不刷新 |
| 顶栏与浮层 | 设置、搜索、通知等浮层可点击外部关闭；私聊等站内页面在列表区显示 |
| 外链预览 | 单击/双击、新标签、刷新、拖动、前进后退、最大化、多预览标签、统一操作图标和动态脚本网页 |
| 原生交互 | 图片继续进入论坛灯箱；带修饰键、新标签目标和下载链接不被脚本接管 |
| LDC 收入 | 只在顶层显示一次，位置正确，点击刷新与页面隐藏恢复正常 |
| 稳定性 | 控制台无脚本异常；连续开关分屏、切换标签和预览后，监听器与 iframe（内嵌页面）数量收敛 |

阅读计数的实站验收只观察正常打开帖子时是否出现预期请求及确认信息，不额外制造请求。

## 4. 预览兼容性回归

预览以网页可运行性为最高优先级。测试必须确认目标页面的外部脚本、内联脚本和模块脚本没有被清理，预览 iframe（内嵌页面）没有 sandbox（沙箱）属性或其他脚本权限限制。

资源保护只验证以下边界：

- 带 `download`（下载）属性的链接保持原生行为。
- 常见压缩包、文档、音视频等二进制目标不做悬停预热。
- 跨域响应超过 8 MiB 时主动中止，避免单页失控占用。
- 重定向后的相对脚本、样式、图片和 `srcset`（响应式图片来源）按最终网址解析。
- 关闭预览功能后，上游监听、样式、请求和 iframe（内嵌页面）运行环境都释放。

这不是内容净化器测试。设置面板已经明确提示完整脚本及 Linux Do 同源能力的风险。

## 5. 发布门禁

发布前必须同时满足：

1. 所有自动化测试和类型检查通过。
2. 构建产物版本与 `package.json` 一致，包含 `@noframes`（不在内嵌页运行），且完整应用只在顶层启动。
3. 真实 Chrome 验收结果已写入 `docs/requirements-audit.md`。
4. `README.md`、技术文档和更新日志与当前行为一致。
5. 仓库不包含 `.env`（环境变量文件）、令牌、登录数据或其他秘密信息。
6. 提交后推送远端；后续每次小修改继续按 Semantic Versioning（语义化版本）更新版本和日志。
