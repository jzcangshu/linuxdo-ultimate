# 需求与审计对照

## 1. 本轮范围

版本 `0.3.3` 针对兼容性、潜在缺陷、长期资源占用、重复代码和发布维护进行系统加固。按用户决定，多账号隔离、临界宽度及其直接关联的分屏适配问题不在本轮修复范围；其余审计项均须有实现、自动化测试或真实浏览器证据。

## 2. 核心需求

| 需求 | 当前实现 | 自动化状态 |
| --- | --- | --- |
| 非阅读页与阅读页互不刷新 | 稳定顶层外壳分别承载列表 iframe（内嵌页面）与帖子页面池 | 已覆盖 |
| 详情页在右或中间 | 沿用原布局模式和用户保存比例 | 已覆盖 |
| 同页多帖子标签 | 标签状态不设硬上限，活动 iframe（内嵌页面）按共享额度调度 | 已覆盖 |
| 标签拖拽排序 | 主、第二阅读区独立排序，拖动时不写状态，放下时只提交一次 | 已覆盖 |
| 第二阅读区 | 标签是移动而非复制，尽量直接转移页面并恢复滚动 | 已覆盖 |
| 刷新恢复与跨访问恢复分离 | 刷新继续当前会话；跨访问默认关闭且只领取最后关闭的一份 | 已覆盖 |
| 阅读计数修复 | 保持 `/pageview`（页面浏览接口）后主题 JSON（结构化主题数据）的原始顺序和确认机制 | 已覆盖 |
| 外链预览 | 移植上游动态运行时，完整执行页面脚本，保留拖动和本项目适配 | 已覆盖 |
| LDC 收入 | 顶层唯一组件、两接口差值、后台暂停、请求复用和短时缓存 | 已覆盖 |
| 设置与原站融合 | 顶栏入口、条件显隐、低高度双列、单次持久化 | 已覆盖 |

## 3. 审计问题闭环

| 审计问题 | 根因或风险 | 处理结果 |
| --- | --- | --- |
| 每个 iframe（内嵌页面）重复解析完整脚本 | 监听、组件和解析成本随标签增长 | 构建加入 `@noframes`（不在内嵌页运行）；轻量桥只由父页安装一次 |
| 桥接存在两套实现 | 自动化曾验证不会发布的旧代码 | 正式实现统一为 `frame-runtime.ts`；旧入口及无效标记测试已移出仓库归档 |
| 分类色在内嵌页读取慢或失败 | 使用父页面构造器判断跨文档元素 | 改用目标文档所属窗口的构造器，并增加跨文档回归测试 |
| 两个阅读区各自计算活动上限 | 实际资源可达到设置值两倍 | 改为共享 `FrameBudget`（页面额度）；只暂停最久未使用的非活动页面 |
| 标签被 50 个硬上限静默丢弃 | 把运行资源限制错误施加到用户状态 | 移除标签状态硬上限；只控制活动页面运行环境 |
| 长期会话和阅读锁持续积累 | 缺少可枚举索引与过期清理 | 增加会话和阅读锁索引；启动时及长期页面每 30 分钟回收，离开页面后停止维护 |
| 存储容量或权限异常造成隐性失败 | 写入异常被吞掉且用户不知情 | 保持页面内存状态，降级后只提示一次，不阻断论坛 |
| 旧页面或同源页面污染标签状态 | 只校验来源域和可预测编号 | 桥接改由父页同一运行域安装，严格核对真实来源窗口、角色编号和帖子身份 |
| 恢复分屏时先露出原生单列页 | 完整应用等待文档结构完成后才启动 | 页面主体出现后立即启动，外壳挂载前遮蔽原生主内容，三个活动框架同轮创建 |
| 阅读框架侧栏和加载标志闪现 | 角色样式直到框架完整加载后才安装 | 内嵌页在父页同步安装角色样式与配置前保持隐藏，随后一次显示 |
| 列表帖子点击无响应 | 拦截原生点击后只发送无确认消息 | 导航消息加入请求编号与父页确认；超时未确认时重放原生点击 |
| 重复就绪造成延迟跳动 | 子页正常就绪和父页加载兜底同时上报 | 删除父页伪造就绪，桥接成为唯一就绪来源 |
| 标签移动后命令永久排队 | 转移时强制把已加载页面改回未加载 | 转移保留加载状态、桥接和命令队列，不等待不会发生的新加载 |
| 拖拽顺序刷新后丢失 | 恢复和打开既有标签按最近使用时间重排 | 标签数组成为唯一顺序来源；活跃时间只用于页面池调度 |
| 滚动恢复触发无限增量加载 | 固定间隔持续强推页面底部 | 仅在匹配网址的真实就绪后定位一次 |
| 新标签和下载链接被误拦截 | 捕获阶段接管范围过宽 | 顶层和内嵌桥都提前保留 `target`（打开目标）、修饰键和 `download`（下载） |
| 预览关闭后仍保留运行时 | 全局监听、样式和页面环境持续占用 | 改为按需安装并可完整卸载；只保留最近三个非活动预览运行环境 |
| 临时缓存到期后仍驻留 | 仅在下一次写缓存时顺带清扫 | 预览按最近到期项安排唯一清理任务；LDC 坏缓存与过期缓存读取时立即删除 |
| 预览重定向后资源失效 | 相对资源仍按初始网址解析 | 使用请求返回的最终网址重写相对资源 |
| 大响应、下载和二进制被误抓取 | 悬停预热可能造成无意义占用 | 下载及常见二进制不预热；单响应超过 8 MiB 中止；缓存按 UTF-16（网页字符串内存表示）估算 |
| 预览网页脚本被限制 | 沙箱仍阻止弹窗、下载和部分导航能力 | 移除 sandbox（沙箱）属性，完整保留目标脚本权限并明确风险 |
| LDC 后台持续请求或并发混算 | 定时、点击和多标签页缺少协调 | 后台暂停、关闭时中止网络、两接口共同提交、Web Locks（网页锁）合并跨页面刷新并共享短时缓存 |
| 设置控件重复写入 | `input`（输入）和 `change`（变更）同时持久化 | 控件只在最终变更时保存；滑块提交后持久化 |
| 操作图标风格分裂 | 字符图标、上游 SVG（可缩放矢量图形）和本地按钮各自绘制 | 统一为 24 单位线性图标系统；预览、设置、标签及右键菜单共同使用 |
| 固定三秒挂载重试脆弱 | 慢设备或论坛异步渲染可能错过宿主 | 改为观察所需 DOM（网页结构）出现后挂载 |
| 路由识别过宽 | 子域或相似路径可能被当成论坛帖子 | 仅接受 `https://linux.do` 和规范 `/t`、`/n` 帖子路径 |
| 测试名称夸大覆盖 | jsdom（浏览器结构模拟器）测试曾被称为浏览器测试 | 改名为 DOM（网页结构）集成冒烟，并把真实 Chrome 验收独立列出 |
| 构建产物大且可能陈旧 | 未压缩，测试直接读取旧 `dist`（发布目录） | 启用语法和空白压缩；构建测试先生成当前版本再校验 |

## 4. 历史高风险缺陷回归

以下问题继续保留自动化或真实验收项，不能因架构加固而复发：

- 滚动帖子时因楼层网址变化反复刷新。
- 阅读页或非阅读页高度被论坛全局 `max-height`（最大高度）截断。
- 列表首次增量加载后无限请求直到页面卡死。
- 阅读页时间轴和底部控制区被错误隐藏。
- 帖子内站内链接覆盖当前阅读标签。
- 图片灯箱被外链预览误接管。
- 二屏列表滚动条出现在浏览器最右侧。
- 分屏刷新后退出分屏。
- 侧栏和顶栏操作导致分屏外壳被整页导航销毁。
- 右键书签错误收藏某个楼层而非整篇主题。

## 5. 明确保留的边界

- 临界宽度与窄视口分屏策略：按用户要求不修复。窄到不适合并排阅读时仍由现有回退逻辑处理。
- 活动页面设置值低于当前可见阅读区数量：可见页面不会被淘汰，因此实际最低保留量等于可见阅读区数量。这是资源额度语义，不是标签数量限制。
- 第三方网页的登录、反内嵌响应头或服务端策略可能让预览失败；脚本不通过限制页面脚本来换取所谓安全兼容。
- 多账号数据隔离：按用户要求不处理；同一浏览器配置默认视为一个论坛账号环境。
